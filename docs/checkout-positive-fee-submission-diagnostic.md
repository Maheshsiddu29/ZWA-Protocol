# Positive-fee two-ZSA submission diagnostic (2026-10-10)

## Verdict

**VALIDATION_TIMEOUT; candidate not accepted.** The first identified failure is the positive-fee transaction's transparent input outpoint. The disposable tx-tool copy takes the height-2 coinbase txid from Zebra's `getblock` RPC and puts its display-order bytes into a serialized transparent outpoint. The serialized outpoint should contain the reverse byte order. Zebra therefore cannot find that UTXO; its pinned block-verification path waits for missing block UTXOs, while the 20-second diagnostic RPC client times out. The exact live verifier task was not instrumented, so the stage is established by the serialized candidate, the independent chain query, and the pinned source path, rather than a task stack trace. No consensus rejection reason was returned to the client.

The node remained alive and responsive at height 307. The candidate block and transaction were absent from RPC lookup. This is not `CLIENT_TIMEOUT_BUT_BLOCK_ACCEPTED` or `NODE_CRASH`. Do not resume checkout development: this candidate has not demonstrated positive-fee acceptance, the prebuilt Action Group fee accounting remains incomplete, and the later rooted-lineage L1 pin rejects the old stack's three-group v6 shape.

## Node result and source check

Immediately after the client timeout, Docker reported `zebrad` running with 46 threads, and fresh RPC queries returned height 307 and the same tip. `getblock` for the candidate hash returned `Block not found`; `getrawtransaction` for its txid returned `Transaction not found`. More than six minutes after submission, the node was still responsive at height 307, and `getblock` again returned `Block not found`. Zebra's info log had no acceptance, rejection, or panic entry for that candidate. The last accepted block was its parent at height 307.

The pinned Zebra transaction verifier calls `AwaitUtxo` for a transparent input absent from the block's known UTXOs (`zebra-consensus/src/transaction.rs`). Its state service checks queued and stored UTXOs and otherwise waits on a pending channel (`zebra-state/src/service.rs`); the state lookup timeout is six minutes. This source path explains the silent 20-second client timeout for the invalid outpoint. The info-level log cannot show an individual pending task, and no node-side verdict appeared even after that nominal bound; the chain result above is the observed result.

## Localized repair and gate

A safe non-frozen tooling repair is to correct RPC transaction-ID byte-order conversion at the boundary, including both `get_block` parsing and `get_transaction` request encoding, with a focused round-trip test using the known height-2 coinbase ID. `send_transaction` response conversion should be audited at the same boundary. A call-site-only reversal would be narrower for this probe but would leave the inconsistent RPC adapter in place. No repair was applied or resubmitted here.

The pinned librustzcash builder's `value_balance()` and `get_fee()` omit prebuilt swap Action Groups. This probe kept their native aggregate at zero and funded the requested fee with a separate transparent pair, so the omission did not create this outpoint timeout. It remains a separate obstacle to a general shielded-fee purchase builder. Do not bypass node validation or treat a local fee assertion as settlement.
