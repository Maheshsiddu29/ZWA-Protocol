# Phase 3.5A ZSA/ZEC purchase-builder recovery (2026-10-10)

## Verdict and evidence boundary

**PROTOCOL_COMPATIBILITY_BLOCKED — NO-GO for checkout UI.** A fresh, zero-network-fee, two-ZSA control swap settled on the old pinned regtest stack. A disposable positive-fee version built and serialized, but `submitblock` timed out twice without an acceptance or rejection verdict. The chain height did not advance. The later rooted-lineage L1 Zebra pin explicitly rejects the control swap's three-Action-Group v6 shape. The required positive-fee control therefore did not pass, and the ZSA-for-ZEC purchase subtask stopped before construction. This verdict records a missing safe, demonstrated path through the pinned implementations; the RPC timeout alone does **not** prove a consensus rule rejects positive fees.

Status terms below mean `PASS` (observed), `FAIL` (observed contrary result), `BLOCKED` (could not establish the required result), and `NOT_TESTED` (not attempted). All amounts are integers: one ZEC is 100,000,000 zatoshis. These are disposable local regtest transactions, not production transactions.

4. **Fee-balance root cause — PASS, source traced.** The Phase 0E tx-tool's `src/components/transactions.rs:753-758` selects `FeeRule::non_standard` with a zero-zatoshi base. Party B's native shielded input pays exactly five zatoshis to the matcher, leaving aggregate swap-group native value balance zero. In pinned librustzcash `zcash_primitives/src/transaction/builder.rs:744-772`, `value_balance()` sums transparent, Sapling, and ordinary Orchard builders but omits prebuilt `self.action_groups`; `build_internal` tests this balance minus the fee at about line 996 before it aggregates and signs those groups at about lines 1072-1103. `get_fee()` likewise counts ordinary Orchard builder actions, not prebuilt swap-group actions. Thus a fee funded only by a prebuilt swap group's ZEC surplus fails the builder precheck or is misestimated. The transaction's final native conservation must account for transparent inputs minus change, all swap-group native inputs minus outputs, and the network fee; custom asset quantities must balance by asset ID. Orchard value commitments and each group's spend authorization feed the aggregate binding signature. A post-signing byte edit would invalidate that authorization.

5. **Minimal change required — BLOCKED for a durable implementation.** The narrow shielded-fee repair is to include each prebuilt Action Group's **checked** native value balance in the builder precheck, count its Actions in fee calculation, select enough native ZEC, and construct the correct signed change/output structure before proving. It also needs regression tests against the exact pinned node. A disposable, library-free probe instead added one mature transparent coinbase input of 625,000,000 zatoshis and transparent change of 624,995,000, giving a requested 5,000-zatoshi fee while keeping the three swap groups' aggregate native balance at zero. Its builder asserted the calculated fee before signing. This was an isolated experiment in `/private/tmp/zwa35a-tx-tool`, not a product or frozen-library patch, and it did not reach acceptance.
